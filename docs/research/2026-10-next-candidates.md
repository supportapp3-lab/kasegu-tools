## 3. 上位3件の仕様案

選定は「既存の検索テーマに、購入前の確認という新しい役割を加えられる」「公式資料が確認できる」「既存計算の再実装を避けられる」を基準にしました。順位や検索需要の推測ではありません。いずれもまず既存URLの強化として検証し、Search Console の実データなしでURLを増やさない案です。

### A. 携帯トイレの箱表示照合

- **URL案:** `/guides/keitai-toilet-bichiku/` の既存ページを強化。新URLは作らない。
- **利用者が記入する項目:** 製品パッケージの「何回分」表示、内訳として書かれた袋・凝固剤等、家にある使用可能回数、確認日。表示が見当たらない項目は空欄のままにする。
- **表示する結果:** 表示を転記した一覧、使用回数と構成品について未確認の項目、自治体の使用後処理案内へのリンク。計算ツールへの既存導線を保つ。
- **数値・出典:** 既存ページの公的目安を引用する場合は、[内閣府の案内](https://www.bousai.go.jp/kohou/kouhoubousai/r06/111/news_08.html)の条件と一緒に記載する。同ページでは「1人35回分／週」の目安が示されているが、利用者属性や自治体運用を一律に置き換えない。千葉市の[トイレ対策](https://www.city.chiba.jp/sogoseisaku/kikikanri/bosai/saigai-toilet-taisaku.html)も参照する。
- **affiliate案:** 既存枠の `toilet` を維持し、パッケージ内訳と在庫確認の説明後、購入前チェックの文脈に置く。凝固剤・袋は #69 §5 の既存カテゴリを使い、特定商品を示さない。
- **相互リンク:** `/tools/toilet-bichiku/` と双方向にリンク。全体備蓄の `/tools/bichiku/` と `/guides/bousai-bichiku/` からも既存導線を確認する。
- **完了条件・テスト案:** 箱の「個数」と「使用回数」を混同しない説明、表示のない項目を推測で補わないこと、自治体案内を明示することをレビュー項目にする。既存のページリンク・affiliate data-category・HTML lint/テストを確認する。

### B. ペットの同行避難・持ち出し記録カード

- **URL案:** `/guides/pet-bousai-bichiku/` の「購入・補充前」または持ち出し確認欄を強化。新URLは作らない。
- **利用者が記入する項目:** ペットごとの普段のフード・用品名、家にある品、識別情報の保管場所、キャリーへの慣れの確認日、自治体の避難先・ルールURL。
- **表示する結果:** 未記入の用品・確認事項と、自治体ルールの再確認リンク。量の計算は既存 `/tools/pet-bichiku/` に任せる。
- **数値・出典:** 新しい数量は使わない。[環境省の災害対策](https://www.env.go.jp/nature/dobutsu/aigo/1_law/disaster.html)に基づき、水・食料・常備薬等、キャリーへの慣れ、自治体ルールの確認を扱う。薬量・食事量・避難可能性を独自判断しない。
- **affiliate案:** #69 §5 の `pet-supply` を用品記録の説明後に置く。キャリーやフード等の既存一般カテゴリを使う場合も、自治体の受入条件を先に確認するよう記載する。
- **相互リンク:** `/tools/pet-bichiku/`、`/guides/bousai-bichiku/`、`/guides/mochidashi-bukuro/`。
- **完了条件・テスト案:** 記録カードは印刷または利用者自身の控えに限定する。医療助言・投薬計算を追加しないこと、環境省・自治体リンク、カテゴリの文脈、内部リンク、lintを確認する。

### C. 乳幼児用品のセット点検表

- **URL案:** `/guides/baby-bousai-bichiku/` を強化。新URLは作らない。
- **利用者が記入する項目:** 家庭で使っているミルク等の種類、子どもごとの衣類・おむつ等のサイズ、必要な付属品、置き場所、確認日。数値の標準値はプリセットしない。
- **表示する結果:** 製品・用品ごとの未確認欄、持ち出し用と在宅用の区分、既存計算ツールへの案内。
- **数値・出典:** 新しい必要量は使わない。[男女共同参画局の備蓄チェックシート](https://www.gender.go.jp/policy/saigai/shishin/pdf/shishin_bichiku_checksheet.pdf)を、用品をセットで考え、各家庭の事情を反映する根拠として参照する。調乳や授乳の方法は製品表示・専門家の案内を優先する。
- **affiliate案:** #69 §5 の `baby-supply`、既存ページで使われている `baby-diaper` / `baby-wipe` を使用。用品セットの点検説明の後に置く。
- **相互リンク:** `/tools/baby-bichiku/`、`/guides/mochidashi-bukuro/`、`/guides/bousai-bichiku/`。

## 4. 見送る候補と理由

- **トイレ使用後のごみ処理を全国一律で決める独立ページ:** 千葉市の案内からも自治体の対応確認が必要と分かるため、全国共通の処理手順にできません。既存トイレガイドに自治体確認リンクを置く範囲にとどめます。
- **蓄電池から使用日数・スマートフォン充電回数を推定する計算機:** 消費者庁の安全情報と既存 `guides/teiden-sonae/` の方針に反し、容量だけで実使用を予測できません。機器と説明書の適合記録なら候補に残します。
- **住所から避難先・安全ルートを自動判定する機能:** ハザードマップと自治体の最新情報、現地状況を置き換えると危険です。公式地図への案内と利用者自身の記録に限定します。
- **家族の災害時連絡先をオンライン保存・共有するサービス:** 個人情報の保管・共有リスクが新たに生まれます。印刷用の記入欄または家庭内の控えを先に検討します。
- **新しい「何日分」備蓄計算機:** 既存の全体・トイレ・乳幼児・ペット計算とテーマが重なります。Search Console で既存URL間のクエリ重複を確認する前に別URLを作らない方がよいです。
- **冬向け商品の需要を前提にした新規ページ:** 今回確認した資料は安全・準備方法の根拠であり、季節ごとの検索需要・購入動向の根拠ではありません。季節性を理由に優先しません。

## 5. Search Console の実データが入ったら見直す点

- ページ・クエリ別に表示回数、クリック、CTR、掲載順位を期間と国・端末をそろえて確認する。これは実測値の確認であり、将来値の予測には使わない。
- 上位3候補に対応する実際のクエリが、候補の検索意図と合っているかを確認する。表示回数だけで購入意図や収益を推定しない。
- #54 第3章で挙げた重複テーマについて、同一クエリに複数URLが表示されるかを確認し、既存URLのタイトル・本文・内部リンクを調整するか判断する。新しいページを追加する判断とは分ける。
- 国・端末・期間で差があるかを見て、季節性を述べる場合は実測期間と比較条件を明記する。十分な比較期間がなければ季節性は結論にしない。
- 検索結果の実データと公開後の変化を蓄積した後に、候補の順序、対象URL、完了条件を再評価する。検索流入・順位・売上の未測定値は埋めない。
